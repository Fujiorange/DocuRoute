## Implementation Details

### 1. Notification System

#### Core Functions (`packages/core/src/notifications.ts`)

**`createNotification(params, tx?)`**:
- Inserts single notification for a user
- Supports transaction context (pass `tx` and `companyId` explicitly)
- Never throws (logs errors, doesn't block operations)

**`createNotificationsForPermission(companyId, targetPermission, notification)`**:
- Finds all roles with target permission (system + custom)
- System roles: checks SYSTEM_ROLE_PERMISSIONS map
- Custom roles: checks permissions[] array (uses GIN index)
- Gets active users with those roles
- Bulk inserts notifications
- Performance: Single query for roles, single query for users, bulk insert

**Transaction Rule**: When called inside `prisma.$transaction()`, pass `tx` client and `companyId` explicitly. The `tx` client does NOT inherit the companyId extension.

#### API Routes

All routes use `withApiHandler()` for error handling and return JSON responses.

**GET /api/notifications**:
- Returns last 50 notifications for `session.userId`
- Ordered by `isRead` ASC (unread first), then `createdAt` DESC
- Uses `getPrismaForCompany()` for multi-tenancy

**POST /api/notifications/[id]/read**:
- Marks notification as read
- Verifies ownership (returns 404 if notification doesn't belong to user)
- Uses `getPrismaForCompany()` for isolation

**POST /api/notifications/read-all**:
- Marks all unread notifications as read for `session.userId`
- Returns count of notifications marked

#### UI Components

**NotificationBell**:
- Bell icon with badge (red dot or count)
- Badge shows:
  - Nothing if unreadCount === 0
  - Number if 1-9
  - "9+" if > 9
- Popover trigger for NotificationDropdown

**NotificationDropdown**:
- Lists recent notifications (max 50, managed by API)
- Unread notifications highlighted with blue dot
- Icons based on notification type (FileText, AlertCircle, Settings, etc.)
- Links to relevant pages (documents, approvals, transmittals, etc.)
- "Mark all read" button (only shows if unread exist)
- Uses `date-fns` formatDistanceToNow for timestamps

**useNotifications Hook**:
- Fetches notifications on mount
- Polls every 30 seconds (only when tab visible via Page Visibility API)
- Provides `markAsRead(id)` and `markAllAsRead()` functions
- Updates local state optimistically (no refetch after mark as read)

### 2. Search System

#### API Route (`/api/documents/search`)

**Features**:
- Permission: `VIEW_DOCUMENT`
- Query parameters:
  - `q` (required): search query
  - `projectId`, `discipline`, `status`: filters
  - `page`, `limit`: pagination (max 100 per page)
- Uses pg_trgm similarity search on `filename` field
- Returns documents with similarity score, ordered by score DESC
- Pagination metadata included in response

**SQL Query**:
```sql
SELECT ... , similarity(filename, $1) AS sml
FROM "Document"
WHERE "companyId" = $2
  AND filename % $3  -- pg_trgm similarity operator
ORDER BY sml DESC, "createdAt" DESC
LIMIT $4 OFFSET $5
```

**Performance**:
- Requires `CREATE EXTENSION pg_trgm;`
- Optional GIN index: `CREATE INDEX idx_document_filename_trgm ON "Document" USING GIN (filename gin_trgm_ops);`
- With index: < 500ms for 1000+ documents

#### UI Components

**GlobalSearchBar**:
- Command palette using shadcn/ui `<Command>` component
- Keyboard shortcut: Cmd+K (Mac) or Ctrl+K (Windows/Linux)
- Debounced search (300ms via `useSearch` hook)
- Shows loading spinner during search
- Result list with document metadata (discipline, status, time)
- Click result → navigate to document page, close dialog

**useSearch Hook**:
- Takes `initialQuery` and `options` (filters, pagination)
- Debounces query changes (300ms)
- Fetches from `/api/documents/search` when query changes
- Returns `results`, `pagination`, `isLoading`, `error`
- Resets results when query is empty

### 3. Onboarding System

#### API Route (`/api/company/onboarding`)

**GET /api/company/onboarding**:
- Returns `CompanyOnboarding` record for `session.companyId`
- Creates record if doesn't exist (with empty `completedSteps[]`)
- No permission gate (any authenticated user can view)

#### Data Model

**CompanyOnboarding**:
- `completedSteps: string[]` - Array of completed step IDs
- Valid step values:
  - `FIRST_PROJECT_CREATED`
  - `FIRST_DOCUMENT_UPLOADED`
  - `FIRST_TEAM_MEMBER_INVITED`
  - `NAMING_MASK_CONFIGURED`
  - `FIRST_WORKFLOW_STARTED`

**Step Completion**: Automatic marking is implemented in Phase 2 within each feature's endpoint (e.g., POST /api/projects marks FIRST_PROJECT_CREATED). For P1P7, manual SQL updates for testing.

#### UI Component

**OnboardingChecklist**:
- Card with progress bar showing `X of 5 completed`
- Lists 5 steps with checkmarks (completed) or circles (pending)
- Each step is a link to relevant page
- Completed steps shown as strikethrough
- Auto-collapses when all 5 steps done
- Manual expand/collapse with chevron button
- Doesn't render if all steps complete and collapsed
- Fetches onboarding status on mount

## Database Requirements

### Prerequisites

**1. GIN Index on Role.permissions** (required for createNotificationsForPermission):
```sql
CREATE INDEX IF NOT EXISTS idx_role_permissions ON "Role" USING GIN (permissions);
```

**2. pg_trgm Extension** (required for search):
```sql
CREATE EXTENSION IF NOT EXISTS pg_trgm;
```

**3. Optional Trigram Index** (improves search performance):
```sql
CREATE INDEX idx_document_filename_trgm ON "Document" USING GIN (filename gin_trgm_ops);
```

### Schema

**Notification** (already exists from Phase 0):
```prisma
model Notification {
  id        String   @id @default(cuid())
  companyId String
  userId    String
  type      String   // NotificationType enum
  title     String
  message   String
  isRead    Boolean  @default(false)
  metadata  Json?
  createdAt DateTime @default(now())
  company   Company  @relation(fields: [companyId], references: [id])

  @@index([userId, isRead])
  @@index([companyId, createdAt])
}
```

**CompanyOnboarding** (already exists from Phase 0):
```prisma
model CompanyOnboarding {
  id             String   @id @default(cuid())
  companyId      String   @unique
  completedSteps String[] @default([])
  createdAt      DateTime @default(now())
  updatedAt      DateTime @updatedAt
  company        Company  @relation(fields: [companyId], references: [id])
}
```

## Performance Considerations

### Notification System

**Polling Strategy**:
- Interval: 30 seconds
- Only polls when tab visible (Page Visibility API)
- Stops polling when tab hidden

**Query Performance**:
- GET /api/notifications: Single query with ORDER BY, LIMIT 50
- createNotificationsForPermission: Uses GIN index on Role.permissions
- Bulk insert: Single createMany for all notifications

**Optimization**:
- GIN index on Role.permissions for fast permission lookups
- Index on Notification (userId, isRead) for fast unread queries
- Index on Notification (companyId, createdAt) for ordering

### Search System

**pg_trgm Performance**:
- Similarity threshold: ~0.3 (configurable)
- GIN index on filename for fast trigram matching
- Pagination to limit result set

**Query Optimization**:
- Uses raw SQL for pg_trgm (Prisma doesn't support % operator)
- Separate count query for pagination metadata
- Both queries run in parallel (Promise.all)

**Benchmarks** (1000 documents):
- Without GIN index: ~2-3s
- With GIN index: ~200-500ms

### Onboarding System

**Minimal Overhead**:
- Single query to fetch CompanyOnboarding
- Creates record only if doesn't exist
- Renders nothing if loading or all complete and collapsed
