# P1P2 Test Guide: Authentication and PBAC Middleware

This guide provides step-by-step instructions for testing the authentication and Permission-Based Access Control (PBAC) middleware implemented in Phase 1, Prompt 2.

## Prerequisites

Before testing, ensure:
1. PostgreSQL database is running (Supabase or local)
2. Required environment variables are set in `.env.local`
3. Database migrations have been applied
4. next-auth version is 4.24.13 (verify with: `grep next-auth apps/web/package.json`)

## Required Environment Variables

Add these to `apps/web/.env.local`:

```bash
# Database
DATABASE_URL="postgresql://..."

# NextAuth
NEXTAUTH_URL="http://localhost:3000"
NEXTAUTH_SECRET="your-secret-key-here"  # Generate with: openssl rand -base64 32

# Email (for magic link authentication)
EMAIL_SERVER_HOST="smtp.resend.com"
EMAIL_SERVER_PORT="587"
EMAIL_SERVER_USER="resend"
EMAIL_SERVER_PASSWORD="your-resend-api-key"
EMAIL_FROM="noreply@yourdomain.com"
```

## Test 1: Verify Installation

**Objective**: Confirm all files are in place and next-auth version is correct.

**Steps**:
1. Check next-auth version:
   ```bash
   grep "next-auth" apps/web/package.json
   ```
   **Expected**: Should show `"next-auth": "^4.24.13"` (NOT beta, NOT v5)

2. Verify files exist:
   ```bash
   ls -la apps/web/src/lib/auth.ts
   ls -la apps/web/src/app/api/auth/[...nextauth]/route.ts
   ls -la apps/web/src/types/next-auth.d.ts
   ls -la apps/web/src/middleware.ts
   ```
   **Expected**: All files should exist

3. Build the project:
   ```bash
   cd /path/to/DocuRoute
   npm run build
   ```
   **Expected**: No TypeScript errors

## Test 2: Permission Resolution

**Objective**: Test that permission resolution works correctly for system and custom roles.

**Steps**:
1. Create a test script `test-permissions.ts`:
   ```typescript
   import { resolvePermissions } from './apps/web/src/lib/auth'
   import { SYSTEM_ROLE_PERMISSIONS, Permission } from '@docuroute/types'

   async function test() {
     // Test system role (you'll need a valid role ID from your DB)
     const roleId = 'your-role-id-here'
     const permissions = await resolvePermissions(roleId)
     console.log('Permissions:', permissions)
   }

   test()
   ```

2. Run the test:
   ```bash
   npx tsx test-permissions.ts
   ```
   **Expected**: Should print an array of Permission enum values

## Test 3: Authentication Flow

**Objective**: Test the complete authentication flow with email magic link.

**Steps**:
1. Start the development server:
   ```bash
   npm run dev
   ```

2. Navigate to `http://localhost:3000/login`

3. Enter a valid user email address (must exist in your User table)

4. Check your email for the magic link

5. Click the magic link

6. **Expected**:
   - Redirected to `/dashboard` (or callback URL)
   - Session is created with user data
   - AuditLog entry for SESSION_STARTED is created

7. Check the AuditLog table:
   ```sql
   SELECT * FROM "AuditLog"
   WHERE action = 'SESSION_STARTED'
   ORDER BY "createdAt" DESC
   LIMIT 1;
   ```
   **Expected**: Recent entry with your user's ID and company ID

## Test 4: Route Protection

**Objective**: Verify middleware protects authenticated routes.

**Steps**:
1. In incognito/private window, try accessing:
   - `http://localhost:3000/dashboard`
   - **Expected**: Redirected to `/login?callbackUrl=/dashboard`

2. Try accessing protected API without auth:
   ```bash
   curl http://localhost:3000/api/users
   ```
   **Expected**: 401 response with `{"error": {"code": "UNAUTHORIZED", ...}}`

3. Try accessing public routes without auth:
   ```bash
   curl http://localhost:3000/api/health
   ```
   **Expected**: 200 response (no authentication required)

## Test 5: Permission Checks

**Objective**: Test requirePermission and requirePermissions functions.

**Steps**:
1. Create a test API route `apps/web/src/app/api/test-permissions/route.ts`:
   ```typescript
   import { NextResponse } from 'next/server'
   import { getServerSession } from 'next-auth'
   import { authOptions } from '@/app/api/auth/[...nextauth]/route'
   import { requirePermission } from '@/lib/auth'
   import { Permission } from '@docuroute/types'

   export async function GET() {
     const session = await getServerSession(authOptions)

     // Convert session to ResolvedUser format
     const user = session?.user ? {
       userId: session.user.userId,
       companyId: session.user.companyId,
       permissions: session.user.permissions,
       roleName: session.user.roleName,
     } : null

     // Test permission check
     requirePermission(user, [Permission.VIEW_DOCUMENT])

     return NextResponse.json({ success: true })
   }
   ```

2. Test with authenticated user:
   ```bash
   # Login first, then use the session cookie
   curl -b cookies.txt http://localhost:3000/api/test-permissions
   ```
   **Expected**:
   - If user has VIEW_DOCUMENT permission: `{"success": true}`
   - If user lacks permission: 403 response

## Test 6: Live Permission Check

**Objective**: Test requireLivePermission for sensitive operations.

**Steps**:
1. Create a test route that uses requireLivePermission:
   ```typescript
   import { requireLivePermission } from '@/lib/auth'
   import { Permission } from '@docuroute/types'

   // In an API route
   await requireLivePermission(
     user,
     [Permission.MANAGE_USERS],
     'test sensitive operation'
   )
   ```

2. Test the route:
   - **Expected**: Function fetches live user from DB and checks current permissions
   - If permission revoked since login: 403 error
   - AuditLog entry created on permission denial

**Objective**: Verify inactive users cannot sign in.

**Steps**:

## Troubleshooting

### Issue: "Module not found" errors
**Solution**: Run `npm install` to ensure all dependencies are installed

### Issue: TypeScript errors about Permission type
**Solution**:
- Verify `@docuroute/types` is built: `npm run build --filter @docuroute/types`
- Check that Permission enum is exported from `packages/types/src/index.ts`

### Issue: Database connection errors
**Solution**:
- Verify DATABASE_URL is correct
- Ensure PostgreSQL is running
- Run migrations: `npx prisma migrate deploy`

### Issue: Email not sending
**Solution**:
- Verify EMAIL_SERVER_* environment variables
- Check Resend API key is valid
- Look for errors in server logs

## Success Criteria

All tests pass if:
- ✅ next-auth version is 4.24.13 (stable v4, not beta)
- ✅ Authentication flow works (magic link → session creation)
- ✅ Protected routes redirect/return 401 when unauthenticated
- ✅ Public routes accessible without authentication
- ✅ Permission checks work (requirePermission, requirePermissions)
- ✅ Live permission checks work (requireLivePermission)
- ✅ Feature flags work (requireFeature)
- ✅ Audit logging works (SESSION_STARTED, SESSION_ENDED)
- ✅ TypeScript types are correct and provide autocomplete
- ✅ Inactive users cannot sign in

## Notes for Beginners

- **What is a magic link?** A one-time login link sent to your email that automatically signs you in when clicked. No password required.

- **What is JWT?** JSON Web Token - a secure way to store session data in a token on the client side instead of in a database.

- **What is middleware?** Code that runs before your page or API route, useful for authentication checks.

- **What is PBAC?** Permission-Based Access Control - checking if a user has specific permissions rather than just checking their role name.

- **Why JWT over database sessions?** For this pilot, JWT is simpler and performs better. For permission revocation on sensitive operations, we use `requireLivePermission` which re-checks the database.
