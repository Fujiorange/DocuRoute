## Test Scenarios

### 1. **Invitation Creation & Email Delivery**

#### Test Case 1.1: Create Invitation with System Role
- **Given**: User has `INVITE_USERS` permission
- **When**: POST `/api/users/invite` with valid email and system role (e.g., DOCUMENT_CONTROLLER)
- **Then**:
  - Invitation record created in DB
  - Token generated (64-char hex)
  - Expiry set to 7 days from now
  - Email sent to recipient with:
    - Company name
    - Inviter name
    - Role name (DOCUMENT_CONTROLLER)
    - Role description (system role)
    - Accept button with magic link
    - Expiry date prominently displayed
  - Audit log entry created: `USER_INVITED`
  - HTTP 201 with invitation details

#### Test Case 1.2: Create Invitation with Custom Role
- **Given**: User has `INVITE_USERS` permission, custom role exists
- **When**: POST `/api/users/invite` with email and custom roleId
- **Then**:
  - Invitation created
  - Email sent with:
    - Role name
    - Up to 5 permissions listed (human-readable labels)
    - "...and X more permissions" if >5
  - HTTP 201

#### Test Case 1.3: Seat Limit Reached
- **Given**: Company at plan seat limit (e.g., 10 users on STARTER)
- **When**: Attempt to invite 11th user
- **Then**:
  - HTTP 402 Payment Required
  - Response body: `{ code: 'SEAT_LIMIT_REACHED', limit: 10, current: 10 }`
  - No invitation created
  - No email sent

#### Test Case 1.4: Duplicate Invitation
- **Given**: Active invitation exists for email@example.com
- **When**: Attempt to invite same email again
- **Then**:
  - HTTP 400 validation error
  - Message: "An active invitation already exists for this email"

#### Test Case 1.5: Invalid Role ID
- **Given**: roleId doesn't belong to company
- **When**: POST with foreign roleId
- **Then**:
  - HTTP 404 not found
  - No invitation created

### 2. **Invitation Validation (Pre-Accept)**

#### Test Case 2.1: Validate Active Token
- **Given**: Valid, unexpired invitation token
- **When**: POST `/api/invitations/validate` with token
- **Then**:
  - HTTP 200
  - Response includes:
    - email
    - roleName
    - isSystemRole
    - systemRoleKey (if system role) or permissions (if custom)
    - companyName
    - expiresAt

- **Given**: Non-existent token
- **When**: POST `/api/invitations/validate`
- **Then**:
  - HTTP 404
  - Error message: "invitation not found"

#### Test Case 2.3: Expired Token
- **Given**: Token with expiresAt < now
- **When**: POST `/api/invitations/validate`
- **Then**:
  - HTTP 400 validation error
  - Message: "This invitation has expired"

#### Test Case 2.4: Already Accepted Token
- **Given**: Invitation with acceptedAt != null
- **When**: POST `/api/invitations/validate`
- **Then**:
  - HTTP 400
  - Message: "This invitation has already been accepted"

### 3. **Invitation Acceptance & User Creation**

#### Test Case 3.1: Accept Valid Invitation
- **Given**: Valid token, name = "John Smith"
- **When**: POST `/api/invitations/accept` with { token, name }
- **Then**:
  - User created with:
    - email from invitation
    - roleId from invitation (FK constraint)
    - companyId from invitation.role.companyId
    - isActive = true
    - name = "John Smith"
  - Invitation.acceptedAt = current timestamp
  - CompanyOnboarding.completedSteps += 'FIRST_TEAM_MEMBER_INVITED' (if not present)
  - Audit log: `USER_INVITED` with { invitationAccepted: true }
  - HTTP 201 with user details

#### Test Case 3.2: Accept with Missing Name

- **When**: POST `/api/invitations/accept`

### 4. **Invitation Resend with Rate Limiting**

#### Test Case 4.1: Resend Valid Invitation
- **Given**: Active invitation, <3 resends in 24h
- **When**: POST `/api/invitations/resend` with { invitationId }
- **Then**:
  - New token generated (invalidates old token)
  - Expiry extended to 7 days from now
  - Email resent with new magic link
  - Audit log: `USER_INVITED` with { resent: true }
  - HTTP 200

#### Test Case 4.2: Rate Limit Exceeded
- **Given**: 3 resends already sent for this email in 24h
- **When**: Attempt 4th resend
- **Then**:
  - HTTP 429 Too Many Requests
  - Error code: `RATE_LIMIT_EXCEEDED`
  - Message includes retry-after time (86400 seconds)
  - No email sent
  - No token regenerated

#### Test Case 4.3: Resend Expired Invitation
- **Given**: Invitation with expiresAt < now
- **When**: POST `/api/invitations/resend`
- **Then**:
  - HTTP 400 validation error
  - Audit log: `PERMISSION_DENIED` with { reason: 'EXPIRED_INVITATION_TOKEN', tokenPrefix }

#### Test Case 4.4: Resend Already-Accepted Invitation
- **Given**: acceptedAt != null
- **When**: POST `/api/invitations/resend`
- **Then**:
  - HTTP 400
  - Message: "This invitation has already been accepted"

#### Test Case 4.5: Resend Foreign Invitation
- **Given**: invitationId belongs to different company
- **When**: User from Company A tries to resend Company B's invitation
- **Then**:
  - HTTP 404 (not 403 — cross-company privacy)

### 8. **Rate Limiting Implementation**

#### Test Case 8.1: Sliding Window Algorithm
- **Given**: Redis available, rate limit config: { limit: 3, windowSeconds: 86400 }
- **When**:
  - T+0s: Resend #1 ✅
  - T+1s: Resend #2 ✅
  - T+2s: Resend #3 ✅
  - T+3s: Resend #4 ❌
- **Then**:
  - First 3 succeed
  - 4th throws `rateLimitExceeded(86400)`

#### Test Case 8.2: Rate Limit Key Format
- **Key**: `ratelimit:invite-resend:email@example.com`
- **TTL**: 2 × windowSeconds (cleanup)

#### Test Case 8.3: Redis Unavailable
- **Given**: UPSTASH_REDIS_REST_URL not set
- **When**: Call `checkRateLimit()`
- **Then**:
  - Throws error: "UPSTASH_REDIS_REST_URL and UPSTASH_REDIS_REST_TOKEN must be set"

## Known Limitations

1. **Email Deliverability**: Resend free tier has send limits. Production should use verified domain.
2. **Rate Limiting Accuracy**: Redis-based sliding window is accurate but requires Redis availability. Fallback to in-memory rate limiting not implemented.
3. **Auto Sign-In**: Uses NextAuth v4 `signIn('credentials')` — requires email/password provider configured. Magic link auto-login not implemented in this phase.
