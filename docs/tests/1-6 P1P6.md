# P1P6 — File Upload with QR Metadata - Test Guide

This guide provides step-by-step instructions for testing the P1P6 file upload implementation. Designed for beginners with basic curl and browser knowledge.

## Prerequisites

Before testing, ensure:

1. **Database migration applied**: Run `npx prisma migrate deploy` in packages/db
2. **Environment variables set**:
   - `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME`
   - `DATABASE_URL` (Supabase PostgreSQL)
   - `NEXTAUTH_SECRET` and `NEXTAUTH_URL`
3. **Development server running**: `npm run dev` in apps/web
4. **User account created** with UPLOAD_DOCUMENT permission

## Test 1: Upload Flow (Normal File <200MB)

### Goal
Verify that files under 200MB upload successfully with no warnings.

### Steps

1. **Authenticate and get session cookie**
   ```bash
   # Login via browser at http://localhost:3000/login
   # Use browser devtools (Network tab) to capture session cookie
   export SESSION_COOKIE="next-auth.session-token=YOUR_TOKEN_HERE"
   ```

2. **Request presign URL**
   ```bash
   curl -X POST http://localhost:3000/api/upload/presign \
     -H "Cookie: $SESSION_COOKIE" \
     -H "Content-Type: application/json" \
     -d '{
       "filename": "test-drawing.pdf",
       "mimeType": "application/pdf",
       "fileSize": 5242880,
       "discipline": "STRUCTURAL",
       "issuePurpose": "FOR_CONSTRUCTION"
     }'
   ```

3. **Expected response** (no warning):
   ```json
   {
     "uploadUrl": "https://...",
     "fileKey": "company123/1234567890-uuid-test-drawing.pdf",
     "expiresAt": "2026-03-16T01:45:00.000Z"
   }
   ```

4. **Upload file to R2**
   ```bash
   # Create test file
   dd if=/dev/zero of=/tmp/test-drawing.pdf bs=1M count=5

   # Upload to presigned URL
   curl -X PUT "PASTE_UPLOAD_URL_HERE" \
     -H "Content-Type: application/pdf" \
     --data-binary @/tmp/test-drawing.pdf
   ```

5. **Compute SHA-256 hash**
   ```bash
   sha256sum /tmp/test-drawing.pdf
   # Copy the hash output
   ```

6. **Confirm upload**
   ```bash
   curl -X POST http://localhost:3000/api/upload/confirm \
     -H "Cookie: $SESSION_COOKIE" \
     -H "Content-Type: application/json" \
     -d '{
       "fileKey": "PASTE_FILE_KEY_HERE",
       "filename": "test-drawing.pdf",
       "sha256Hash": "PASTE_HASH_HERE",
       "fileSize": 5242880,
       "mimeType": "application/pdf",
       "discipline": "STRUCTURAL",
       "issuePurpose": "FOR_CONSTRUCTION"
     }'
   ```

7. **Expected response**:
   ```json
   {
     "documentId": "clx...",
     "status": "PENDING",
     "watermarkStatus": "PENDING"
   }
   ```

8. **Verify in database**
   ```sql
   SELECT id, filename, fileSize, watermarkStatus, metadata
   FROM "Document"
   WHERE filename = 'test-drawing.pdf';
   ```

   Expected: watermarkStatus = 'PENDING', metadata = NULL

### Troubleshooting

- **401 Unauthorized**: Session cookie expired. Re-login and get new cookie.
- **400 File type not allowed**: Check filename extension is in allowlist (.pdf, .dwg, .dxf, .xlsx, .docx, .png, .jpg)
- **404 File not found in storage**: R2 upload failed. Check R2 credentials and bucket name.
- **500 R2 credentials not configured**: Set R2 environment variables

## Test 2: Watermark Size Gate (FOR_CONSTRUCTION >200MB)

### Goal
Verify that FOR_CONSTRUCTION files >200MB trigger warning and require acknowledgment.

### Steps

1. **Request presign URL for 250MB file**
   ```bash
   curl -X POST http://localhost:3000/api/upload/presign \
     -H "Cookie: $SESSION_COOKIE" \
     -H "Content-Type: application/json" \
     -d '{
       "filename": "large-drawing.pdf",
       "mimeType": "application/pdf",
       "fileSize": 262144000,
       "discipline": "PIPING",
       "issuePurpose": "FOR_CONSTRUCTION"
     }'
   ```

2. **Expected response** (with warning):
   ```json
   {
     "uploadUrl": "https://...",
     "fileKey": "company123/...",
     "expiresAt": "2026-03-16T01:45:00.000Z",
     "warning": {
       "proceedAllowed": true,
       "warning": "WATERMARK_SKIPPED_TOO_LARGE",
       "requiresAcknowledgment": true,
       "message": "This file exceeds 200MB. QR status verification cannot be embedded..."
     }
   }
   ```

3. **Upload file to R2** (same as Test 1 step 4, but with 250MB file)
   ```bash
   dd if=/dev/zero of=/tmp/large-drawing.pdf bs=1M count=250
   curl -X PUT "PASTE_UPLOAD_URL_HERE" \
     -H "Content-Type: application/pdf" \
     --data-binary @/tmp/large-drawing.pdf
   ```

4. **Compute SHA-256 hash**
   ```bash
   sha256sum /tmp/large-drawing.pdf
   ```

5. **Confirm upload WITHOUT acknowledgment** (should fail)
   ```bash
   curl -X POST http://localhost:3000/api/upload/confirm \
     -H "Cookie: $SESSION_COOKIE" \
     -H "Content-Type: application/json" \
     -d '{
       "fileKey": "PASTE_FILE_KEY_HERE",
       "filename": "large-drawing.pdf",
       "sha256Hash": "PASTE_HASH_HERE",
       "fileSize": 262144000,
       "mimeType": "application/pdf",
       "discipline": "PIPING",
       "issuePurpose": "FOR_CONSTRUCTION"
     }'
   ```

6. **Expected response** (422 error):
   ```json
   {
     "error": {
       "code": "ACKNOWLEDGMENT_REQUIRED",
       "message": "Acknowledgment required for oversized FOR_CONSTRUCTION files"
     }
   }
   ```

7. **Confirm upload WITH acknowledgment** (should succeed)
   ```bash
   curl -X POST http://localhost:3000/api/upload/confirm \
     -H "Cookie: $SESSION_COOKIE" \
     -H "Content-Type: application/json" \
     -d '{
       "fileKey": "PASTE_FILE_KEY_HERE",
       "filename": "large-drawing.pdf",
       "sha256Hash": "PASTE_HASH_HERE",
       "fileSize": 262144000,
       "mimeType": "application/pdf",
       "discipline": "PIPING",
       "issuePurpose": "FOR_CONSTRUCTION",
       "acknowledgedWatermarkSkip": true
     }'
   ```

8. **Expected response**:
   ```json
   {
     "documentId": "clx...",
     "status": "PENDING",
     "watermarkStatus": "SKIPPED_TOO_LARGE",
     "warning": "QR verification unavailable for this file (size exceeds 200MB)"
   }
   ```

9. **Verify metadata in database**
   ```sql
   SELECT id, filename, watermarkStatus, metadata
   FROM "Document"
   WHERE filename = 'large-drawing.pdf';
   ```

   Expected:
   - watermarkStatus = 'SKIPPED_TOO_LARGE'
   - metadata contains:
     ```json
     {
       "watermarkSkipped": true,
       "reason": "TOO_LARGE_FOR_CONSTRUCTION",
       "acknowledgedByUserId": "user_xxx",
       "acknowledgedAt": "2026-03-16T01:23:45.678Z"
     }
     ```

### Troubleshooting

- **Presign succeeds but no warning**: Check that fileSize > 209715200 (200 * 1024 * 1024)
- **Confirm succeeds without acknowledgment**: Bug in watermark gate logic. Check issuePurpose === 'FOR_CONSTRUCTION' condition.

## Test 5: QR Verification Page (Public Access)

### Goal
Verify that public QR verification page works without authentication and displays correct status.

### Steps

1. **Create test document in database** (using Test 1 or Test 2 above)
   Copy documentId from confirm response.

2. **Visit verification page in incognito window** (no login):
   ```
   http://localhost:3000/verify/PASTE_DOCUMENT_ID_HERE
   ```

3. **Expected behavior**:
   - Page loads without authentication prompt
   - Full-screen background color based on status
   - Large headline text
   - Document details displayed:
     - Document code (filename)
     - Revision (hardcoded 'A' for Phase 1)
     - Issue purpose
     - Discipline
     - Project name
   - Timestamp at bottom

4. **Test different statuses**:

   a. **ACTIVE + FOR_CONSTRUCTION** (green background):
      - Update document in DB: `UPDATE "Document" SET status = 'ACTIVE' WHERE id = '...'`
      - Refresh page, verify green background and "SAFE FOR CONSTRUCTION" headline

   b. **SUPERSEDED** (red background):
      - Update document: `UPDATE "Document" SET status = 'SUPERSEDED' WHERE id = '...'`
      - Refresh page, verify red background and "SUPERSEDED — DO NOT USE" headline

   c. **Watermark skipped** (amber note):
      - For document from Test 2 (>200MB FOR_CONSTRUCTION), verify amber note appears:
        "Note: This document does not have an embedded QR code. This verification was performed by document ID lookup."

5. **Verify audit logging**:
   ```sql
   SELECT action, metadata
   FROM "AuditLog"
   WHERE "resourceId" = 'PASTE_DOCUMENT_ID_HERE'
   AND action = 'DOCUMENT_DOWNLOADED'
   ORDER BY "createdAt" DESC
   LIMIT 5;
   ```

   Expected: metadata contains `{ "scanType": "QR_FIELD_VERIFICATION", "isSafe": true/false }`

6. **Verify vault logging for unsafe documents**:
   ```sql
   SELECT "eventType", metadata
   FROM "AuditVaultEntry"
   WHERE metadata->>'documentId' = 'PASTE_DOCUMENT_ID_HERE'
   ORDER BY "createdAt" DESC
   LIMIT 1;
   ```

   Expected (for SUPERSEDED document): eventType = 'SUPERSEDED_DOC_ACKNOWLEDGED'

## Troubleshooting Common Issues

### Issue: "R2 credentials not configured"

**Solution**: Set environment variables in `.env.local`:
```
R2_ACCOUNT_ID=your_account_id
R2_ACCESS_KEY_ID=your_access_key
R2_SECRET_ACCESS_KEY=your_secret_key
R2_BUCKET_NAME=your_bucket_name
```

### Issue: "File not found in storage"

**Causes**:
1. R2 upload failed (check network logs)
2. Wrong bucket name
3. Presigned URL expired (>15 minutes)

**Solution**: Check R2 dashboard for uploaded objects, verify bucket name matches

### Issue: 401 Unauthorized on API routes

**Solution**: Ensure session cookie is valid. Login again and get fresh cookie.

### Issue: Migration not applied

**Solution**:
```bash
cd /home/runner/work/DocuRoute/DocuRoute
npx prisma migrate deploy --schema=packages/db/prisma/schema.prisma
```

### Issue: TypeScript errors in components

**Solution**: Ensure types are built:
```bash
cd packages/types && npm run build
cd packages/core && npm run build
cd packages/db && npx prisma generate
```
