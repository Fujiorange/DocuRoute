# P1P4 — User Management System: Test Guide

This document provides a beginner-friendly test guide for the user management system implemented in P1P4.

## Prerequisites

Before testing, ensure:
1. You have a running DocuRoute instance (local or staging)
2. You have access to the database (Supabase dashboard or psql)
3. You have at least one company created
4. You have test users with different permission levels

## Setting Up Test Environment

### Create Test Users with Different Permissions

Run this SQL in your Supabase SQL Editor:

```sql
-- First, find your test company ID
SELECT id, name FROM "Company" WHERE name LIKE '%test%';

-- Find the role IDs you'll need
SELECT id, name, "isSystemRole", "systemRoleKey"
FROM "Role"
WHERE "companyId" = 'YOUR_COMPANY_ID'
ORDER BY "isSystemRole" DESC, name;

-- Create test users (or update existing ones)
-- User 1: Company Admin (can manage users and invite)
UPDATE "User"
SET "roleId" = (
  SELECT id FROM "Role"
  WHERE "companyId" = 'YOUR_COMPANY_ID'
  AND "systemRoleKey" = 'COMPANY_ADMIN'
)
WHERE email = 'admin@test.com';

-- User 2: Document Controller (can only view, no user management)
UPDATE "User"
SET "roleId" = (
  SELECT id FROM "Role"
  WHERE "companyId" = 'YOUR_COMPANY_ID'
  AND "systemRoleKey" = 'DOCUMENT_CONTROLLER'
)
WHERE email = 'controller@test.com';

-- User 3: Custom role with only INVITE_USERS permission
-- (First create a custom role if you don't have one)
INSERT INTO "Role" (id, "companyId", name, "isSystemRole", permissions, "createdAt", "updatedAt")
VALUES (
  gen_random_uuid()::text,
  'YOUR_COMPANY_ID',
  'HR Manager',
  false,
  ARRAY['INVITE_USERS']::text[],
  NOW(),
  NOW()
);

-- Assign user to HR Manager role
UPDATE "User"
SET "roleId" = (
  SELECT id FROM "Role"
  WHERE "companyId" = 'YOUR_COMPANY_ID'
  AND name = 'HR Manager'
)
WHERE email = 'hr@test.com';
```

### Check Current Seat Count

```sql
-- Count active users (excluding BILLING_CONTACT)
SELECT COUNT(*) as active_seats
FROM "User" u
JOIN "Role" r ON u."roleId" = r.id
WHERE u."companyId" = 'YOUR_COMPANY_ID'
  AND u."isActive" = true
  AND NOT (r."isSystemRole" = true AND r."systemRoleKey" = 'BILLING_CONTACT');

-- View all users with their roles
SELECT
  u.email,
  u.name,
  u."isActive",
  r.name as role_name,
  r."isSystemRole",
  r."systemRoleKey"
FROM "User" u
JOIN "Role" r ON u."roleId" = r.id
WHERE u."companyId" = 'YOUR_COMPANY_ID'
ORDER BY u."isActive" DESC, u."createdAt" DESC;
```

### Test 3: Invite User (Happy Path)

**Purpose:** Verify that inviting a new user works correctly.

**Steps:**
1. Log in as admin@test.com
2. Navigate to `/dashboard/settings/users`
3. Click "Invite User" button
4. Fill in the form:
   - Email: newuser@test.com
   - Name: New User
   - Role: Document Controller (or any valid role)
5. Click "Send Invitation"
6. Check browser DevTools → Network tab for POST to `/api/users/invite`

**Expected Response:**
```json
{
  "invitation": {
    "id": "invitation_id_123",
    "email": "newuser@test.com",
    "roleId": "role_id_456",
    "roleName": "Document Controller",
    "expiresAt": "2026-03-22T12:30:00.000Z",
    "magicLink": "http://localhost:3000/auth/accept-invite?token=abc123..."

```

**Database Verification:**
```sql
-- Check that invitation was created
SELECT * FROM "Invitation"
WHERE email = 'newuser@test.com'
ORDER BY "createdAt" DESC
LIMIT 1;

-- Check audit log
SELECT * FROM "AuditLog"
WHERE action = 'USER_INVITED'
  AND metadata->>'email' = 'newuser@test.com'
ORDER BY "createdAt" DESC
LIMIT 1;
```

**Verification:**
- ✅ Modal closes after successful submission
- ✅ API returns 201 status
- ✅ Invitation record created in database
- ✅ Token is unique and properly formatted
- ✅ expiresAt is 7 days in the future
- ✅ AuditLog entry created with correct action

### Test 12: Audit Trail Verification

**Purpose:** Verify that all user management operations are properly logged.

**Steps:**
Perform the following operations:
1. Invite a user
2. Change a user's role
3. Deactivate a user

**Database Verification:**
```sql
-- Check all audit logs for your company
SELECT
  action,
  metadata->>'email' as email,
  metadata->>'targetUserEmail' as target_email,
  "permissionsUsed",
  "createdAt"
FROM "AuditLog"
WHERE "companyId" = 'YOUR_COMPANY_ID'
  AND action IN ('USER_INVITED', 'USER_ROLE_CHANGED', 'USER_DEACTIVATED')
ORDER BY "createdAt" DESC
LIMIT 10;
```

**Expected Results:**
- ✅ USER_INVITED log includes:
  - email, roleId, roleName in metadata
  - permissionsUsed: ["INVITE_USERS"]
- ✅ USER_ROLE_CHANGED log includes:
  - targetUserId, targetUserEmail
  - fromRoleId, fromRoleName, toRoleId, toRoleName in metadata
  - permissionsUsed: ["MANAGE_USERS"]
- ✅ USER_DEACTIVATED log includes:
  - targetUserId, targetUserEmail, targetUserName
  - roleId, roleName in metadata
  - permissionsUsed: ["DEACTIVATE_USERS"]
- ✅ All logs have userId (who performed action)
- ✅ All logs have ipAddress and userAgent (if available)

**Status:** ☐ Pass ☐ Fail
