# P1P7 Testing Guide: Notifications, Search, Onboarding, UI Shell

**Purpose**: This guide helps you verify that P1P7's notification system, search functionality, onboarding checklist, and UI shell components work correctly.

**Prerequisites**:
- P1P0-P1P6 completed and tested
- GIN index on Role.permissions table
- pg_trgm extension enabled in PostgreSQL
- At least 2 users in different roles

## PART 1: Notification System

### Test 1.1: Core Notification Functions

**Setup**:
```bash
# Verify GIN index exists
psql $DATABASE_URL -c "SELECT indexname FROM pg_indexes WHERE tablename = 'Role' AND indexname = 'idx_role_permissions';"
# Should return: idx_role_permissions
```

**Test createNotification**:
```typescript
// In Node.js REPL or test file
import { createNotification } from '@docuroute/core/src/notifications'
import { NotificationType } from '@docuroute/types'

await createNotification({
  companyId: 'your-company-id',
  userId: 'test-user-id',
  type: NotificationType.DOCUMENT_QUARANTINED,
  title: 'Document Quarantined',
  message: 'Document ABC-123 was quarantined by virus scan',
  metadata: { documentId: 'doc-123' }
})
```

✅ **Expected**: Notification created in database
❌ **If fails**: Check console for errors, verify companyId and userId exist

**Test createNotificationsForPermission**:
```typescript
import { createNotificationsForPermission } from '@docuroute/core/src/notifications'
import { Permission, NotificationType } from '@docuroute/types'

// This should notify all users with APPROVE_WORKFLOW permission
await createNotificationsForPermission(
  'your-company-id',
  Permission.APPROVE_WORKFLOW,
  {
    type: NotificationType.WORKFLOW_ACTION_REQUIRED,
    title: 'Approval Required',
    message: 'Document XYZ-456 requires your approval',
    metadata: { documentId: 'doc-456' }
  }
)
```

✅ **Expected**: Notifications created for all users with APPROVE_WORKFLOW permission (check both system roles like DOCUMENT_CONTROLLER and custom roles)
❌ **If fails**: Verify GIN index exists, check that roles have the permission

## PART 2: Search System

### Test 2.1: Search API

**Test GET /api/documents/search**:
```bash
# Basic search
curl "http://localhost:3000/api/documents/search?q=drawing" \
  -H "Cookie: next-auth.session-token=YOUR_SESSION_TOKEN"

# With filters
curl "http://localhost:3000/api/documents/search?q=plan&discipline=STRUCTURAL&status=ACTIVE&page=1&limit=20" \
  -H "Cookie: next-auth.session-token=YOUR_SESSION_TOKEN"
```

✅ **Expected**: JSON with `documents` array and `pagination` object
❌ **If 403**: User lacks VIEW_DOCUMENT permission
❌ **If 500 about pg_trgm**: Run `CREATE EXTENSION IF NOT EXISTS pg_trgm;` in SQL Editor

**Verify pg_trgm similarity**:
```sql
-- Should return documents similar to query, ranked by similarity
SELECT filename, similarity(filename, 'drawing') AS sml
FROM "Document"
WHERE "companyId" = 'your-company-id'
  AND filename % 'drawing'
ORDER BY sml DESC
LIMIT 10;
```

## Common Issues

### Issue: Notifications not polling
**Fix**: Check Page Visibility API is working. Open browser DevTools → Console, type:
```javascript
document.addEventListener('visibilitychange', () => console.log('Visibility changed:', document.hidden))
```
Switch tabs, should log messages.

### Issue: Search returns no results despite matching documents
**Fix**: Verify pg_trgm extension:
```sql
SELECT * FROM pg_extension WHERE extname = 'pg_trgm';
-- If empty, run: CREATE EXTENSION pg_trgm;
```

### Issue: createNotificationsForPermission doesn't find custom roles
**Fix**: Verify GIN index exists:
```sql
CREATE INDEX IF NOT EXISTS idx_role_permissions ON "Role" USING GIN (permissions);
```
