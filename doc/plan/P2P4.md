# P2P4: Vendor Company Management - Implementation Prompt

## Context

You are implementing **Phase 2, Prompt 4 (P2P4)** for **DocuRoute**, an ISO 9001 compliant document management system for shipbuilding, offshore platforms, and heavy industrial projects. DocuRoute is a pnpm monorepo with:
- **apps/web**: Next.js 14 app with NextAuth v4.24.13, TypeScript, Tailwind CSS
- **apps/worker**: Node.js BullMQ worker for background jobs
- **packages/db**: Prisma ORM with PostgreSQL (Supabase)
- **packages/core**: Shared business logic (no React/Next.js imports)
- **packages/types**: Shared TypeScript types
- **packages/emails**: React Email templates

**Phase 1 Status**: User authentication, PBAC authorization, document management, project management, custom roles, invitations, search, and notifications are fully implemented.

**Phase 2 Progress**: P2P1 (Equipment Hierarchy Management) and P2P3 (Project Templates) are complete.

**Your Mission**: Implement Vendor Company Management to handle vendor contacts in a GDPR/PDPA compliant manner, manage vendor submissions with technical data packages, and automatically trigger document review workflows when vendors submit packages.

---

## Requirements

### Business Context

Shipyards work with hundreds of vendors across multiple projects. Vendors must submit technical data packages, installation manuals, test certificates, and as-built drawings. The system must:
1. Handle vendor contacts with GDPR/PDPA compliance
2. Manage vendor submissions with document packages
3. Automatically trigger review workflows when vendors submit packages
4. Link vendor submissions to specific equipment items
5. Track submission status and review progress

model VendorCompany {

```prisma
model VendorSubmission {
  id              String        @id @default(cuid())
  companyId       String
  vendorCompanyId String
  projectId       String
  equipmentId     String?       // Link submission to specific equipment
  submissionCode  String        // Auto-generated: "VS-2026-001"
  title           String

  submittedAt     DateTime?
  reviewedAt      DateTime?
  reviewedBy      String?
  reviewComments  String?

  // Review workflow integration (CRITICAL FIX)
  requiredDisciplines String[]  // ["MECHANICAL", "ELECTRICAL", "HVAC"] - triggers DisciplineReviewStatus creation
  autoCreateReview Boolean      @default(true)  // If true, auto-create DocumentRevision + Review round on SUBMITTED

  metadata        Json?
  createdAt       DateTime      @default(now())
  updatedAt       DateTime      @updatedAt

  company         Company       @relation(fields: [companyId], references: [id])
  vendorCompany   VendorCompany @relation(fields: [vendorCompanyId], references: [id])
  project         Project       @relation(fields: [projectId], references: [id])
  equipment       Equipment?    @relation(fields: [equipmentId], references: [id])
  documents       Document[]    @relation("VendorSubmissionDocuments")

  @@unique([companyId, submissionCode])
  @@index([vendorCompanyId, status])
  @@index([projectId, status])
  @@index([equipmentId])
}
```

### API Endpoints

Implement the following API routes in `apps/web/src/app/api/`:

1. **POST /api/vendors** - Create vendor company
   - Input: `{ name, code, country, portalEnabled, portalUrl }`
   - Output: Vendor company ID
   - Permission: `VENDOR_MANAGE`

2. **GET /api/vendors?companyId={id}** - List vendors
   - Query params: `search`, `page`, `limit`
   - Returns: Paginated vendor list with contact counts
   - Permission: `VENDOR_MANAGE`

3. **GET /api/vendors/{id}** - Get vendor details
   - Returns: Vendor with contacts and submission counts
   - Permission: `VENDOR_MANAGE`

4. **PATCH /api/vendors/{id}** - Update vendor company
   - Permission: `VENDOR_MANAGE`

5. **DELETE /api/vendors/{id}** - Delete vendor
   - Validation: Cannot delete if has submissions
   - Permission: `VENDOR_MANAGE`

6. **POST /api/vendors/{id}/contacts** - Add vendor contact
   - Input: `{ email, name, phone, role, notes }`
   - Validation: Check uniqueness per vendor
   - Permission: `VENDOR_CONTACT_MANAGE`

7. **GET /api/vendors/{id}/contacts** - List vendor contacts
   - Returns: Active contacts only by default
   - Permission: `VENDOR_MANAGE`

8. **PATCH /api/vendor-contacts/{id}** - Update contact
   - Permission: `VENDOR_CONTACT_MANAGE`

9. **DELETE /api/vendor-contacts/{id}** - Soft delete contact
   - Sets `isActive = false`
   - Permission: `VENDOR_CONTACT_MANAGE`

10. **GET /api/vendor-contacts/{id}/export-pii** - GDPR data export
    - Returns: JSON with all contact data
    - Permission: `VENDOR_CONTACT_MANAGE`

11. **POST /api/vendors/{id}/submissions** - Create vendor submission
    - Input: `{ title, projectId, equipmentId, requiredDisciplines, documentIds }`
    - Output: Submission code
    - Permission: `VENDOR_MANAGE`

12. **GET /api/vendor-submissions?projectId={id}&status={status}** - List submissions
    - Query params: `vendorCompanyId`, `status`, `equipmentId`, `page`, `limit`
    - Returns: Paginated submissions
    - Permission: `VENDOR_SUBMISSION_REVIEW`

13. **GET /api/vendor-submissions/{id}** - Get submission details
    - Returns: Submission with documents and review status
    - Permission: `VENDOR_SUBMISSION_REVIEW`

14. **PATCH /api/vendor-submissions/{id}/submit** - Submit vendor package
    - Input: `{ requiredDisciplines, autoCreateReview }`
    - Triggers: Auto-create DocumentRevision + DisciplineReviewStatus
    - Returns: `{ revisionsCreated, disciplineStatusesCreated, notificationsSent }`
    - Permission: `VENDOR_SUBMISSION_TRIGGER_REVIEW`

15. **PATCH /api/vendor-submissions/{id}/review** - Approve/reject submission
    - Input: `{ status: "APPROVED" | "REJECTED", reviewComments }`
    - Permission: `VENDOR_SUBMISSION_REVIEW`

### Core Business Logic

Implement in `packages/core/src/vendors.ts`:

#### Vendor Submission Workflow Trigger
```typescript
// Triggered on: VendorSubmission.status = "DRAFT" → "SUBMITTED"
async function onVendorSubmissionSubmitted(
  submissionId: string,
  tx?: PrismaClient
): Promise<{
  revisionsCreated: number;
  disciplineStatusesCreated: number;
  notificationsSent: number;
}>;
```

**Behavior**:
1. Fetch submission with documents
2. If `autoCreateReview = false`, skip review workflow
3. For each document:
   - Create first DocumentRevision (reviewRound = 1)
   - Use existing document fileKey, fileSize, sha256Hash
   - Create DisciplineReviewStatus for each required discipline
   - Send notifications to reviewers with `DOCUMENT_REVIEW` permission
4. Update submission status to "UNDER_REVIEW"
5. Create audit vault entry
6. Return counts
