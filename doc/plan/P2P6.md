# P2P6: QR / Barcode Field Execution Layer - Implementation Prompt

## Context

You are implementing **Phase 2, Prompt 6 (P2P6)** for **DocuRoute**, an ISO 9001 compliant document management system for shipbuilding, offshore platforms, and heavy industrial projects. DocuRoute is a pnpm monorepo with:
- **apps/web**: Next.js 14 app with NextAuth v4.24.13, TypeScript, Tailwind CSS
- **apps/worker**: Node.js BullMQ worker for background jobs
- **packages/db**: Prisma ORM with PostgreSQL (Supabase)
- **packages/core**: Shared business logic (no React/Next.js imports)
- **packages/types**: Shared TypeScript types
- **packages/emails**: React Email templates

**Phase 1 Status**: User authentication, PBAC authorization, document management, project management, custom roles, invitations, search, and notifications are fully implemented. Document QR codes (P1P6) are already implemented.

**Phase 2 Progress**: P2P1 (Equipment Hierarchy), P2P3 (Project Templates), P2P4 (Vendor Management), and P2P5 (BIM Integration) are complete.

**Your Mission**: Implement QR/Barcode Field Execution Layer to enable field engineers to scan equipment QR codes, view current status, upload commissioning photo evidence, manage punch items, and work offline with conflict resolution.

---

## Requirements

### Business Context

Field engineers work in environments without reliable internet (dry docks, offshore platforms, sea trials). Every equipment item must have a printable QR code for offline verification. Engineers scan QR codes with tablets to:
1. View current equipment revision, lifecycle stage, and open comments
2. Upload photo evidence for commissioning sign-off
3. Record field inspections (installation verify, commissioned, damage report)
4. Manage punch items (defects, non-conformances)
5. Execute commissioning tests with witness signatures
6. Work offline and sync when connection restored

### API Endpoints

Implement the following API routes in `apps/web/src/app/api/`:

1. **GET /api/equipment/{id}/qr-code?format=png&size=256&mode=REFERENCE_ONLY** - Generate QR code
   - Query params: `format`, `size`, `mode`
   - Returns: PNG image or Data Matrix code
   - Permission: `QR_CODE_GENERATE`

2. **POST /api/equipment/qr-codes/bulk** - Bulk QR generation for printing
   - Input: `{ equipmentIds[], format: "pdf", pageSize: "A4", codesPerPage: 24 }`
   - Returns: PDF with QR codes and labels
   - Permission: `QR_CODE_GENERATE`

3. **POST /api/field-inspections** - Submit field inspection
   - Input: `{ equipmentId, inspectionType, status, notes, photoKeys[], checklistItems[], timestamp }`
   - Permission: `FIELD_INSPECTION_CREATE`

4. **POST /api/field-inspections/sync** - Offline sync (batch)
   - Input: `{ inspections[] }`
   - Returns: Sync results with conflicts
   - Permission: `FIELD_INSPECTION_CREATE`

5. **GET /api/field-inspections?equipmentId={id}&projectId={id}** - List inspections
   - Permission: `FIELD_INSPECTION_VIEW`

6. **POST /api/commissioning-records** - Create commissioning record
   - Input: `{ equipmentId, recordType, testData, witnesses[] }`
   - Permission: `COMMISSIONING_RECORD_CREATE`

7. **GET /api/commissioning-records/start?equipmentId={id}** - Start commissioning (loads template)
   - Returns: Template with test steps and data fields
   - Permission: `COMMISSIONING_RECORD_CREATE`

8. **PATCH /api/commissioning-records/{id}** - Update commissioning record
   - Permission: `COMMISSIONING_RECORD_CREATE`

9. **PATCH /api/commissioning-records/{id}/verdict** - Set verdict (PASS/FAIL)
   - Input: `{ verdict, witnesses[] }`
   - Auto-updates Equipment.lifecycleStage if PASS
   - Permission: `COMMISSIONING_RECORD_APPROVE`

10. **GET /api/commissioning-templates?equipmentType={type}** - Get templates
    - Permission: `COMMISSIONING_RECORD_CREATE`

11. **POST /api/commissioning-templates** - Create template
    - Permission: `COMMISSIONING_TEMPLATE_MANAGE`

12. **POST /api/punch-items** - Create punch item
    - Input: `{ equipmentId, description, severity, assignedTo, photoKeys[] }`
    - Auto-generates item number
    - Permission: `PUNCH_ITEM_CREATE`

13. **GET /api/punch-items?projectId={id}&status={status}&severity={severity}** - List punch items
    - Query params: `equipmentId`, `assignedTo`, `status`, `severity`
    - Permission: `FIELD_INSPECTION_VIEW`

14. **PATCH /api/punch-items/{id}/status** - Update status
    - Permission: `PUNCH_ITEM_RESOLVE`

15. **POST /api/punch-items/{id}/escalate** - Escalate punch item
    - Increments escalation level
    - Sends notifications
    - Permission: `PUNCH_ITEM_RESOLVE`

16. **POST /api/offline-sync/submit** - Submit offline edits
    - Input: `{ edits[] }` with Lamport timestamps
    - Returns: Conflicts detected
    - Permission: `FIELD_INSPECTION_CREATE`

17. **GET /api/offline-sync/conflicts** - Get unresolved conflicts
    - Permission: `FIELD_INSPECTION_CREATE`

18. **POST /api/offline-sync/resolve-conflict** - Resolve conflict
    - Input: `{ editId, resolution: "KEEP_MINE" | "KEEP_THEIRS" | "MANUAL_OVERRIDE", value }`
    - Permission: `FIELD_INSPECTION_CREATE`

### Core Business Logic

Implement in `packages/core/src/field-execution.ts`:

#### QR Code Generation
```typescript
interface QRPayloadConfig {
  mode: QRPayloadMode;
  includeLinkedDocs?: boolean;
  compressMetadata?: boolean;
}

async function generateEquipmentQRCode(
  equipmentId: string,
  config: QRPayloadConfig,
  format: "png" | "svg" | "datamatrix"
): Promise<Buffer>;
```

**Behavior**:
- REFERENCE_ONLY: `https://docuroute.com/e/{shortId}` (33 bytes)
- MINIMAL_OFFLINE: `{ t: "TAG", n: "Name", l: "STAGE", s: epoch }` (~80 bytes)
- DATA_MATRIX: Full equipment + linked docs (~5-10KB, requires Data Matrix code)
- Encrypt payload with company-specific AES-256 key
- Return image buffer

#### Offline Conflict Detection
```typescript
interface OfflineEdit {
  deviceId: string;
  entityType: string;
  entityId: string;
  field: string;
  oldValue: any;
  newValue: any;
  lamportTimestamp: number;
  physicalTimestamp: Date;
  userId: string;
}

async function detectOfflineConflicts(
  edits: OfflineEdit[]
): Promise<Array<{
  edit: OfflineEdit;
  conflictsWith: OfflineEdit[];
  suggestedResolution: "AUTO_MERGE" | "LAST_WRITE_WINS" | "MANUAL";
}>>;
```

**Behavior**:
1. Group edits by entityType + entityId + field
2. For each group:
   - If multiple devices edited same field → conflict
   - Compare Lamport timestamps for ordering
   - For non-critical fields (notes, photos): AUTO_MERGE (concatenate)
   - For critical fields (lifecycleStage, verdict): LAST_WRITE_WINS + flag for manual review
3. Return conflicts with suggested resolutions
