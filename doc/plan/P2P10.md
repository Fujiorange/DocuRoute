# P2P10: Multi-Round Document Review & Conditional Approval - Implementation Prompt

## Context

You are implementing **Phase 2, Prompt 10 (P2P10)** for **DocuRoute**, an ISO 9001 compliant document management system for shipbuilding, offshore platforms, and heavy industrial projects. DocuRoute is a pnpm monorepo with:
- **apps/web**: Next.js 14 app with NextAuth v4.24.13, TypeScript, Tailwind CSS
- **apps/worker**: Node.js BullMQ worker for background jobs
- **packages/db**: Prisma ORM with PostgreSQL (Supabase)
- **packages/core**: Shared business logic (no React/Next.js imports)
- **packages/types**: Shared TypeScript types
- **packages/emails**: React Email templates

**Phase 1 Status**: User authentication, PBAC authorization, document management, project management, custom roles, invitations, search, and notifications are fully implemented. Basic document review exists from Phase 1.

**Phase 2 Progress**: P2P1 (Equipment Hierarchy), P2P3 (Project Templates), P2P4 (Vendor Management), P2P5 (BIM Integration), P2P6 (Field Execution), P2P7 (Classification Society), P2P8 (Audit Ledger), and P2P9 (Storage Quota) are complete.

**Your Mission**: Implement Multi-Round Document Review with conditional approval, review round tracking, supersession chains, RFI (Request for Information) workflow, multi-discipline review consolidation, markup support, and optimistic locking for concurrent editing.

---

## Requirements

### Business Context

Vendor drawing review cycles in shipyards typically go through 2-4 rounds: IFR (Issued for Review) → IFA (Issued for Approval) → IFC (Issued for Construction) → AB (As-Built). Conditional approval ("Approved subject to corrections") is extremely common. The system must track review rounds, supersession chains, and conditional approval conditions.

### Database Schema Changes

Enhance existing `DocumentRevision` model in `packages/db/prisma/schema.prisma`:

```prisma
model DocumentRevision {
  // ... existing fields from Phase 1 ...
  reviewRound     Int       @default(1)  // 1, 2, 3, 4 (increments with each review cycle)
  supersededById  String?   // Link to newer revision that supersedes this one
  supersedes      DocumentRevision? @relation("RevisionSupersession", fields: [supersededById], references: [id])
  supersededBy    DocumentRevision[] @relation("RevisionSupersession")

  reviews         Review[]
  equipmentDocLinks EquipmentDocument[]
  printLogs       PrintLog[]
```

Add new `Review` model:

```prisma
model Review {
  id                  String            @id @default(cuid())
  companyId           String
  documentId          String
  revisionId          String
  reviewRound         Int               // Must match DocumentRevision.reviewRound

  reviewerUserId      String
  reviewerName        String
  reviewerRole        String?           // "ENGINEERING_MANAGER" | "QA_QC" | "PROJECT_MANAGER" | etc.
  discipline          String?           // "MECHANICAL" | "ELECTRICAL" | "STRUCTURAL" | "HVAC" | etc.

  decision            String            // "APPROVED" | "APPROVED_WITH_CONDITIONS" | "REJECTED" | "REVISE_AND_RESUBMIT" | "RFI_REQUIRED"
  conditions          String?           // Required if decision = "APPROVED_WITH_CONDITIONS"
  comments            String?

  // RFI Integration
  requiresRfi         Boolean           @default(false)  // True if reviewer raises RFI
  rfiReference        String?           // Link to external RFI system or internal RFI ID
  rfiResolvedAt       DateTime?         // When RFI was resolved
  rfiResolution       String?           // Summary of RFI resolution

  // Attachment support for review comments with markups
  markupFileKey       String?           // R2 key for PDF with review annotations

  reviewedAt          DateTime          @default(now())
  createdAt           DateTime          @default(now())

  company             Company           @relation(fields: [companyId], references: [id])
  document            Document          @relation(fields: [documentId], references: [id])
  revision            DocumentRevision  @relation(fields: [revisionId], references: [id])

  @@index([documentId, reviewRound])
  @@index([revisionId])
  @@index([reviewerUserId, reviewedAt])
  @@index([companyId, decision])
  @@index([requiresRfi, rfiResolvedAt])
}
```

Add new `DisciplineReviewStatus` model:

```prisma
model DisciplineReviewStatus {
  id                  String            @id @default(cuid())
  companyId           String
  documentId          String
  revisionId          String
  reviewRound         Int

  discipline          String            // "MECHANICAL" | "ELECTRICAL" | "STRUCTURAL" | "HVAC" | "PIPING"
  status              String            @default("PENDING")  // "PENDING" | "IN_PROGRESS" | "COMPLETED"
  consolidatedDecision String?          // Discipline-level decision after all reviewers submit
  completedAt         DateTime?

  company             Company           @relation(fields: [companyId], references: [id])
  document            Document          @relation(fields: [documentId], references: [id])
  revision            DocumentRevision  @relation(fields: [revisionId], references: [id])

  @@unique([documentId, revisionId, discipline])
  @@index([companyId, status])
}
```

### API Endpoints

Implement the following API routes in `apps/web/src/app/api/`:

1. **POST /api/documents/{id}/revisions/{revId}/review** - Submit review
   - Input: `{ decision, conditions?, comments?, discipline?, requiresRfi?, markupFileKey? }`
   - Validation: `conditions` required if `decision = "APPROVED_WITH_CONDITIONS"`
   - Permission: `DOCUMENT_REVIEW`

2. **GET /api/documents/{id}/review-history** - Get review history
   - Returns: All review rounds with reviews and supersession chain
   - Permission: `DOCUMENT_REVIEW_VIEW`

3. **POST /api/documents/{id}/revisions/new-round** - Create new revision after review
   - Input: `{ previousRevisionId, changes, fileKey, requiredDisciplines[] }`
   - Auto-increments reviewRound
   - Creates supersession link
   - Auto-creates DisciplineReviewStatus entries
   - Permission: `DOCUMENT_UPLOAD`

4. **POST /api/documents/{id}/revisions/{revId}/acknowledge-conditions** - Acknowledge conditional approval
   - Input: `{ acknowledgedBy, acknowledgementNotes }`
   - Permission: `DOCUMENT_REVIEW_ACKNOWLEDGE`

5. **GET /api/documents/{id}/rfis** - Get all RFIs for document
   - Returns: All reviews with `requiresRfi = true`
   - Permission: `DOCUMENT_REVIEW_VIEW`

6. **POST /api/documents/{id}/rfis/{reviewId}/respond** - Vendor responds to RFI
   - Input: `{ responseText, attachmentKeys[] }`
   - Permission: `DOCUMENT_UPLOAD`

7. **POST /api/documents/{id}/rfis/{reviewId}/resolve** - Reviewer resolves RFI
   - Input: `{ rfiResolution, newDecision }`
   - Sets `rfiResolvedAt = now()`
   - Updates review decision
   - Permission: `DOCUMENT_REVIEW`

8. **GET /api/documents/{id}/revisions/{revId}/discipline-status** - Get discipline review progress
   - Returns: DisciplineReviewStatus for all disciplines
   - Permission: `DOCUMENT_REVIEW_VIEW`

9. **POST /api/documents/{id}/revisions/{revId}/consolidate** - Manually trigger consolidation
   - Admin-only manual consolidation override
   - Permission: `REVIEW_CONSOLIDATE`

10. **POST /api/documents/{id}/revisions/{revId}/checkout** - Check out revision for editing
    - Sets `lockedBy` and `lockedUntil`
    - Prevents concurrent edits
    - Permission: `DOCUMENT_CHECKOUT`

11. **POST /api/documents/{id}/revisions/{revId}/checkin** - Check in revision
    - Clears `lockedBy`
    - Increments `version` (optimistic locking)
    - Permission: `DOCUMENT_CHECKOUT`

12. **POST /api/documents/{id}/revisions/{revId}/unlock** - Force unlock (admin)
    - Admin force unlock for abandoned locks
    - Permission: `REVIEW_CONSOLIDATE`

### Core Business Logic

Implement in `packages/core/src/multi-round-review.ts`:

#### Submit Review
```typescript
async function submitReview(
  documentId: string,
  revisionId: string,
  review: {
    reviewerUserId: string;
    reviewerName: string;
    discipline?: ReviewDiscipline;
    decision: ReviewDecision;
    conditions?: string;
    comments?: string;
    requiresRfi?: boolean;
    markupFileKey?: string;
  }
): Promise<string>; // Returns review ID
```

**Behavior**:
1. Validate `conditions` required if decision = "APPROVED_WITH_CONDITIONS"
2. Create Review record
3. Update DisciplineReviewStatus if discipline provided:
   - Set status = "IN_PROGRESS"
   - Check if all reviewers for discipline submitted
   - If yes, consolidate discipline decision
4. Send notification to document owner
5. Return review ID

#### Create New Review Round
```typescript
async function createNewReviewRound(
  documentId: string,
  previousRevisionId: string,
  newFileKey: string,
  changes: string,
  requiredDisciplines: ReviewDiscipline[]
): Promise<string>; // Returns new revision ID
```

**Behavior**:
1. Get previous revision
2. Create new DocumentRevision:
   - `reviewRound = previousRevision.reviewRound + 1`
   - `supersededById = previousRevisionId`
3. Create DisciplineReviewStatus for each required discipline
4. Send notifications to discipline reviewers
5. Return new revision ID

#### Consolidate Discipline Review
```typescript
async function consolidateDisciplineReview(
  revisionId: string,
  discipline: ReviewDiscipline
): Promise<{
  status: DisciplineReviewStatus;
  consolidatedDecision: ReviewDecision;
}>;
```

**Behavior**:
1. Fetch all reviews for this revision and discipline
2. Apply consolidation rules:
   - If ANY reviewer = "REJECTED" → `consolidatedDecision = "REJECTED"`
   - If ANY reviewer = "REVISE_AND_RESUBMIT" → `consolidatedDecision = "REVISE_AND_RESUBMIT"`
   - If ALL reviewers = "APPROVED" → `consolidatedDecision = "APPROVED"`
   - If mixed "APPROVED" + "APPROVED_WITH_CONDITIONS" → `consolidatedDecision = "APPROVED_WITH_CONDITIONS"`
3. Update DisciplineReviewStatus:
   - `status = "COMPLETED"`
   - `consolidatedDecision = ...`
   - `completedAt = now()`
4. Return status

#### Check Document Approval Status
```typescript
async function checkDocumentApprovalStatus(
  documentId: string,
  revisionId: string
): Promise<{
  canAdvance: boolean;
  pendingDisciplines: string[];
  openRfis: number;
}>;
```

**Behavior**:
1. Check all DisciplineReviewStatus entries
2. Check all reviews with `requiresRfi = true` and `rfiResolvedAt = null`
3. Return:
   - `canAdvance = true` if all disciplines completed and no open RFIs
   - `pendingDisciplines` list
   - `openRfis` count


**Behavior**:

## Quality Standards

Follow Phase 1 and Phase 2 patterns. Use TypeScript strict mode, Zod validation, transaction-wrapped operations, optimistic locking for concurrency.

### Performance
- Review submission: <500ms
- Discipline consolidation: <1 second
- Review history query: <2 seconds (paginated)
- Supersession chain: <1 second
- **Add composite indexes for common queries:**
  - `@@index([documentId, reviewRound, discipline])` on Review for discipline filtering
  - `@@index([revisionId, decision])` for decision summaries
  - `@@index([revisionId, status])` on DisciplineReviewStatus for pending disciplines
  - `@@index([documentId, discipline, completedAt])` for discipline history
- Paginate review history (default 50, max 100 per page)
- When fetching reviews, use includes to avoid N+1 queries on reviewer details

### Security
- Validate permissions before all operations
- Prevent review without DOCUMENT_REVIEW permission
- Log all review decisions to audit trail
- Validate revision locked before edits
- Prevent concurrent edits
