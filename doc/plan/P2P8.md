## Requirements

### Business Context

When shipyards hand over the as-built documentation package to vessel owners, they need cryptographic proof that no documents were altered post-delivery. This has legal value in arbitration cases and insurance claims.

**Legal Defensibility Requirements**:
- Hash chain alone (internal system) = NOT sufficient for most arbitration/insurance claims
- Owners and lawyers will not trust "vendor SaaS says chain is intact"
- **Solution**: Optional anchoring to external timestamp authorities or blockchain for independent verification

### Hash Chain Architecture

**Concept**:
- Every document revision, lifecycle transition, transmittal submission, and classification society submission generates an AuditVaultEntry
- Each entry includes:
  - Hash of the entry's own data
  - Hash of the PREVIOUS entry (creating a blockchain-style chain)
  - Document fingerprint (SHA-256 of the file content at that moment)

**Chain Integrity**:
- If any historical entry is tampered with, the chain breaks
- System provides verification API that recomputes entire chain and confirms integrity
- Exportable audit package includes full hash list for owner verification

```prisma
model AuditVaultEntry {
  // ... existing fields from Phase 1 ...
  hash                String   // SHA-256 of this entry's content
  previousHash        String?  // SHA-256 of previous entry (null for first entry)
  chainIndex          Int      // Sequential index in the chain for this company
  documentFingerprint String?  // SHA-256 of document file (for document-related events)

  // Optional external anchoring
  anchorType          String?  // "OPENTIMESTAMPS" | "BITCOIN" | "ETHEREUM" | "IRON_MOUNTAIN" | null
  anchorProof         String?  // Proof data from anchoring service (OTS file, tx hash, etc.)
  anchoredAt          DateTime?

  @@index([companyId, chainIndex])
  @@unique([companyId, chainIndex])
}
```

Add new model for batch anchoring:

```prisma
model AuditAnchorBatch {
```

### API Endpoints

Implement the following API routes in `apps/web/src/app/api/`:

1. **GET /api/audit-chain/verify?companyId={id}** - Verify chain integrity
   - Returns: `{ valid: boolean, chainLength: number, lastVerifiedAt: Date, brokenAt?: number }`
   - Permission: `AUDIT_CHAIN_VIEW`

2. **GET /api/audit-chain/export?projectId={id}&format=json|pdf** - Export audit package
   - Query params: `projectId` (optional, exports all if omitted), `format`
   - Returns: JSON or PDF with full hash chain
   - Permission: `AUDIT_CHAIN_EXPORT`
   - Note: Use streaming for large chains (>10,000 entries)

3. **GET /api/documents/{id}/audit-trail** - Get document audit trail
   - Returns: All AuditVaultEntry records for this document with hash verification
   - Permission: `AUDIT_CHAIN_VIEW`

4. **POST /api/audit-chain/anchor** - Create anchor batch
   - Input: `{ anchorType: "OPENTIMESTAMPS" | "BITCOIN" | "ETHEREUM" | "IRON_MOUNTAIN", startIndex?, endIndex? }`
   - Creates merkle tree from batch of entries
   - Submits to anchoring service
   - Returns: `{ batchId, merkleRoot, estimatedCost }`
   - Permission: `AUDIT_CHAIN_ANCHOR`

5. **GET /api/audit-anchor-batches?companyId={id}** - List anchor batches
   - Returns: All anchor batches with verification URLs
   - Permission: `AUDIT_CHAIN_VIEW`

6. **GET /api/audit-anchor-batches/{id}/verify** - Verify anchor batch
   - Verifies merkle root against blockchain/timestamp service
   - Returns: `{ valid: boolean, anchoredAt: Date, verificationUrl: string }`
   - Permission: `AUDIT_CHAIN_VIEW`

### Core Business Logic

Implement in `packages/core/src/audit-chain.ts`:

#### Hash Calculation
```typescript
function computeAuditHash(
  entry: AuditVaultEntry,
  previousHash: string | null
): string;
```

**Behavior**:
```typescript
const payload = JSON.stringify({
  chainIndex: entry.chainIndex,
  companyId: entry.companyId,
  eventType: entry.eventType,
  userId: entry.userId,
  userEmail: entry.userEmail,
  createdAt: entry.createdAt.toISOString(),
  metadata: entry.metadata,
  documentFingerprint: entry.documentFingerprint,
  previousHash: previousHash
});
return crypto.createHash('sha256').update(payload, 'utf8').digest('hex');
```

#### Chain Verification
```typescript
async function verifyAuditChain(
  companyId: string
): Promise<{ valid: boolean; brokenAt?: number; chainLength: number }>;
```

**Behavior**:
1. Fetch all entries for company ordered by chainIndex
2. Iterate through each entry:
   - Recompute hash using `computeAuditHash()`
   - Compare to stored hash
   - Verify previousHash matches previous entry's hash
   - If mismatch, return `{ valid: false, brokenAt: chainIndex }`
3. Return `{ valid: true, chainLength }`

#### Audit Chain Export
```typescript
async function exportAuditChain(
  companyId: string,
  projectId?: string,
  format: "json" | "pdf"
): Promise<AuditChainExport | Buffer>;
```

**Behavior**:
1. Fetch all entries for company (filtered by project if provided)
2. Fetch all anchor batches
3. Construct export object with full chain
4. If format = "json", return JSON string
5. If format = "pdf", generate formatted PDF report
6. Include verification instructions

#### Merkle Tree Construction
```typescript
function buildMerkleTree(
  entries: AuditVaultEntry[]
): { root: string; proof: string[] };
```

**Behavior**:
1. Create leaf nodes from entry hashes
2. Build binary tree by hashing pairs
3. Return merkle root and proof array

#### Anchoring Service Integration
```typescript
async function anchorToOpenTimestamps(
  merkleRoot: string
): Promise<{ proof: string; verificationUrl: string }>;

async function anchorToBitcoin(
  merkleRoot: string
): Promise<{ txHash: string; verificationUrl: string }>;

async function anchorToEthereum(
  merkleRoot: string
): Promise<{ txHash: string; verificationUrl: string }>;

async function anchorToIronMountain(
  merkleRoot: string
): Promise<{ certificate: string; verificationUrl: string }>;
```

**Anchoring Options**:

1. **OpenTimestamps** (Recommended):
   - Free Bitcoin-based timestamping
   - Submit merkle root → get .ots proof file
   - Verification: Anyone can verify using OpenTimestamps tools
   - Cost: ~$0

2. **Bitcoin**:
   - Submit merkle root as OP_RETURN transaction
   - Permanent record on public blockchain
   - Cost: ~$5-20 per anchor

3. **Ethereum**:
   - Submit merkle root to smart contract
   - Permanent record on Ethereum blockchain
   - Cost: ~$10-50 per anchor (gas fees)

4. **Iron Mountain**:
   - Commercial timestamp authority
   - Notarized timestamp certificates
   - Cost: ~$50-200 per batch

#### Background Job: Daily Chain Verification
```typescript
// BullMQ worker job
async function verifyAllCompanyChains(): Promise<void>;
```

**Behavior**:
1. Fetch all companies
2. For each company, run `verifyAuditChain()`

4. Log verification result

### Performance
- **CRITICAL**: Chain verification will scan millions of rows - use cursor-based pagination:
  ```typescript
  // ✅ GOOD: Cursor-based pagination with batch size 1000
  let cursor: string | undefined
  while (true) {
    const entries = await prisma.auditVaultEntry.findMany({
      where: {
        companyId,
        ...(cursor ? { chainIndex: { gt: parseInt(cursor) } } : {})
      },
      orderBy: { chainIndex: 'asc' },
      take: 1000
    })
    if (entries.length === 0) break
    // Verify batch in parallel
    cursor = entries[entries.length - 1].chainIndex.toString()
  }
  ```
- Chain verification: <5 seconds for 10,000 entries (with pagination)
- Export: Stream large chains (>10,000 entries) - don't load all into memory
- Merkle tree: <2 seconds for 1,000 entries
- Daily verification: Run during off-peak hours
- Add indexes: `[companyId, createdAt]`, `[companyId, eventType, createdAt]`, `[documentFingerprint]`

### Security
- Use SHA-256 for all hashing
- Database-level unique constraint on chainIndex
- Prevent manual audit entry deletion (soft delete only)
- Log all export operations
- Validate merkle proofs before anchoring
