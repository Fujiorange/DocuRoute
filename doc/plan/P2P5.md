# P2P5: BIM / 3D Model Integration - Implementation Prompt

## Context

You are implementing **Phase 2, Prompt 5 (P2P5)** for **DocuRoute**, an ISO 9001 compliant document management system for shipbuilding, offshore platforms, and heavy industrial projects. DocuRoute is a pnpm monorepo with:
- **apps/web**: Next.js 14 app with NextAuth v4.24.13, TypeScript, Tailwind CSS
- **apps/worker**: Node.js BullMQ worker for background jobs
- **packages/db**: Prisma ORM with PostgreSQL (Supabase)
- **packages/core**: Shared business logic (no React/Next.js imports)
- **packages/types**: Shared TypeScript types
- **packages/emails**: React Email templates

**Phase 1 Status**: User authentication, PBAC authorization, document management, project management, custom roles, invitations, search, and notifications are fully implemented.

**Phase 2 Progress**: P2P1 (Equipment Hierarchy Management), P2P3 (Project Templates), and P2P4 (Vendor Company Management) are complete.

**Your Mission**: Implement BIM / 3D Model Integration to enable one-way import of equipment lists from AVEVA Marine, Tribon, Cadmatic, and Catia with tag normalization, conflict resolution, and audit trail logging.

---

## Requirements

### Business Context

Shipyards already have 3D models in AVEVA Marine, Tribon, Cadmatic, or Catia. Equipment tags and hierarchy are defined in these systems first. Manual re-entry into DocuRoute wastes time and introduces errors. Direct import saves approximately 400 man-hours per newbuild project.

**Critical Reality Check**: BIM systems do NOT expose public REST APIs for bidirectional sync. This is a **one-way import** from CSV/JSON/XML exports. Manual export from BIM system → Import into DocuRoute.

**Key Challenge**: BIM systems export messy tag formats (paths, brackets, suffixes). Tag normalization engine must clean tags before validation.

### Integration Architecture

**One-Way Import Flow**:
1. User exports equipment list from BIM system as CSV/JSON/XML
2. User uploads file to DocuRoute
3. Tag Normalization Engine processes raw tags using company-configured rules
4. System shows before/after preview for user approval
5. System validates normalized tags against company `EquipmentTagFormat` rules
6. System auto-creates Equipment records with proper parent-child links (transaction-wrapped)
7. System optionally creates placeholder documents for each equipment
8. System logs import with full source file checksum for audit trail

### Core Business Logic

Implement in `packages/core/src/bim-integration.ts`:

#### Tag Normalization Engine
```typescript
interface TagNormalizationRule {
  id: string;
  name: string;
  bimSystem: string;
  priority: number;
  patternRegex: string;
  extractTemplate: string;
  transformType?: TagTransformType;
  examples: Array<{ input: string; output: string }>;
}

async function normalizeEquipmentTag(
  tag: string,
  bimSystem: BIMSystem,
  companyId: string
): Promise<TagNormalizationResult>;
```

**Behavior**:
1. Fetch all active normalization rules for company and BIM system
2. Sort by priority
3. Apply each rule in sequence:
   - Test regex pattern
   - Extract using capture groups
   - Apply transform (uppercase, add dashes, etc.)
4. Return normalized tag with rules applied

**Example Rules**:
```typescript
// Extract tag from brackets: "Main Engine [ME-01]" → "ME-01"
const bracketExtractor = {
  pattern: /\[([A-Z0-9-]+)\]/,
  extract: "$1"
};

// Extract from AVEVA path: "/Equipment/Hull1/EngineRoom/ME-01" → "ME-01"
const pathExtractor = {
  pattern: /\/Equipment\/[^/]+\/[^/]+\/([A-Z0-9-]+)$/,
  extract: "$1"
};

// Convert underscores to dashes: "ME_01" → "ME-01"
const underscoreToDash = {
  pattern: /([A-Z0-9]+)_([A-Z0-9]+)/g,
  extract: "$1-$2"
};

// Strip revision suffix: "ME-01-REV-B" → "ME-01"
const stripRevision = {
  pattern: /^([A-Z0-9-]+)[-_](REV|R|V)[-_]?[A-Z0-9]*$/,
  extract: "$1"
};
```

#### BIM Equipment Import
```typescript
async function importBIMEquipment(
  projectId: string,
  source: BIMSystem,
  equipment: BIMImportEquipment[],
  options: {
    updateExisting: boolean;
    createPlaceholderDocuments: boolean;
    modelId?: string;
  },
  userId: string
): Promise<{
  importLogId: string;
  recordsImported: number;
  recordsUpdated: number;
  recordsSkipped: number;
  conflicts: Array<{ tag: string; issue: string; action: string }>;
}>;
```

**Behavior**:
1. Calculate file checksum (SHA-256)
2. Start transaction
3. For each equipment item:
   - Normalize tag using normalization engine
   - Validate against company tag format rules
   - Check if equipment exists with same tag
   - If exists and `updateExisting=true`, update
   - If exists and `updateExisting=false`, skip and log conflict
   - If not exists, create new equipment
   - Set `bimModelId`, `bimCoordinates`, `bimLastImportedAt`
   - If `createPlaceholderDocuments=true`, create placeholder docs
4. Create parent-child relationships after all equipment created
5. Create BIMImportLog with full stats
6. Commit transaction
7. Return results

#### Conflict Resolution
```typescript
async function resolveBIMConflict(
  equipmentId: string,
  action: "OVERWRITE" | "KEEP_EXISTING" | "MERGE",
  newData: Partial<Equipment>,
  userId: string
): Promise<void>;
```

**Behavior**:
- OVERWRITE: Replace all fields with new data
- KEEP_EXISTING: Keep existing, ignore import
- MERGE: Smart merge (keep existing if non-null, use new if existing is null)
- Log resolution to audit trail

- **CRITICAL**: Batch equipment creation (100 items per batch) with smaller transactions to avoid timeouts:
  ```typescript
  const BATCH_SIZE = 100
  for (let i = 0; i < equipment.length; i += BATCH_SIZE) {
    const batch = equipment.slice(i, i + BATCH_SIZE)
    await prisma.$transaction(async (tx) => {
      // Process batch items
    }, {
      timeout: 15000 // 15 second timeout per batch
    })
  }
  ```
- **IMPORTANT**: Importing 10,000+ items in single transaction WILL timeout - use batching
- Use BullMQ for imports >1000 items with progress tracking
- Stream large CSV files (don't load entire file into memory)
- Optimize parent-child relationship creation - use batch operations
- For large imports, return import log ID immediately and process asynchronously
- Add progress callback for UI updates during batch processing
